The goal

Train our own small model, from scratch, that finds its way home in the dark the way the fly does: by rewriting its own connection strengths as it walks, not by holding a number in its head.

The trick we are copying

There are two ways a brain can keep a running total. Try both. The agent takes ten steps north, one per second, then stops. Watch what each memory does with the number 10 during the twenty seconds of standing still.

Hold it in your head · activity

Each second the memory repeats its number to itself, multiplied by the gain, then adds the new step. Gain must be exactly 1. Drag it either way.

Tally marks · synapses

Each step adds a mark. Nothing repeats. Standing still changes nothing. There is no gain to tune, because "do nothing" is already exact.

This is the whole argument in one slider. A memory held in activity must feed itself back with gain exactly 1, and every published model of path integration, and every language model holding your conversation, works this way. A memory held in synapses only needs a "write" signal and an "erase" signal. The fly has candidate neurons for both: dopamine (FB4M, FB5H) to write while walking, octopamine (OA-VPM3) to erase at food. That is what we are copying.
Go deeper why gain is so fragile

After n seconds of holding, an activity memory has multiplied its number by gainn. At gain 0.99 and 60 seconds, 0.9960 is about 0.55, so almost half the memory is gone. At 1.01 it has grown by 1.8 times. Real neurons are noisy and their strengths drift, so hitting 1.000 and staying there needs either constant correction or a network shaped so that errors cancel, which is what a ring attractor does. Even then, published estimates of drift in the fly compass are a few degrees per minute. A synaptic sum has no such term: its only leak is the fade, and doing nothing has a fade of zero.

Go deeper why these choices
  • Perfect compass. The fly has one and how it works is understood. We are not studying the compass, so giving it free keeps the question sharp: can the brain add up steps?
  • Random turning of 0.8 times the square root of the tick. This is a random walk in heading. The square root makes the wobble come out the same no matter how fine the ticks are. 0.8 gives paths that wander a few units in 30 seconds, like a real fly in Kim's 2017 arena.
  • Walking forward only. Real flies can sidestep, and the fly brain has a stage (the PFN neurons) that combines heading with body-relative motion to get true travel direction. That stage is understood, so we skip it.
  • A plane, not 3D. Walking flies are on a surface, the compass is a ring with no "up," and all the behavioural data we compare against is from flat arenas.
The code, explained world.py
# world.py  – the game every level plays in. Plain numpy, no learning here.
import numpy as np

DT     = 0.1    # seconds per tick. Small enough that a step is a small move,
                # big enough that a 90 s trip is only 900 ticks.
T_OUT  = 30.0   # seconds of random wandering before the switch flips
T_RET  = 60.0   # seconds the brain gets to drive home before we give up

def new_trip(rng):
    # A dict is just a bag of named numbers. We use one so every part of the
    # agent's state travels together and any function can read or change it.
    return dict(
        x=0.0, y=0.0,                  # position; food is at (0, 0), so we start ON the food
        hd=rng.uniform(0, 2*np.pi),    # heading in radians, random so no trip is the same
        speed=1.0, pause=0,            # pause counts down ticks of standing still
        t=0.0, phase='out',            # phase is 'out', then 'ret', then 'done'
        min_d=np.inf, arrived=False)   # min_d: closest we ever got to food on the return

def update_speed(s, rng):
    if s['pause'] > 0:                 # mid-pause: stand still, count down
        s['pause'] -= 1; s['speed'] = 0.0; return
    if rng.random() < 0.01:            # 1 % chance per tick to start a pause
        s['pause'] = int(rng.uniform(1, 3) / DT)   # 1 to 3 seconds long
    # Speed drifts like a random walk but is pulled back toward 1.0 (the 0.2*(1-speed) term)
    # and clipped so it never stops or sprints. This makes speed vary, which matters
    # at level 1 for testing whether writing should scale with speed.
    s['speed'] = np.clip(s['speed'] + 0.3*rng.normal()*np.sqrt(DT) + 0.2*(1-s['speed'])*DT, 0.3, 1.7)

def move(s, turn, rng):
    # turn: what the brain asks for, in radians per second. Only obeyed on the return.
    if s['phase'] == 'out': turn = 0.0
    # Heading gets the brain's turn plus random wobble. The sqrt(DT) makes the wobble
    # independent of tick size (this is how you discretise a random walk correctly).
    s['hd'] += turn*DT + 0.8*rng.normal()*np.sqrt(DT)
    s['x']  += s['speed']*np.cos(s['hd'])*DT    # walk forward along the heading
    s['y']  += s['speed']*np.sin(s['hd'])*DT
    s['t']  += DT
    d = np.hypot(s['x'], s['y'])                 # distance from food, Pythagoras
    if s['phase'] == 'out' and s['t'] >= T_OUT: s['phase'] = 'ret'   # the switch flips
    if s['phase'] == 'ret':
        s['min_d'] = min(s['min_d'], d)          # remember the best we did
        if d < 0.5: s['arrived'] = True          # within half a unit: home
        if s['t'] >= T_OUT + T_RET: s['phase'] = 'done'   # out of time

Go deeper the four parts as math

Direction cells. Cell i sits at angle θi = i × 45°. Its activity is max(0, cos(θi − heading)). A heading between two cells lights both partway, so eight cells can represent any direction, and when the reader adds the columns as arrows the true direction comes back out.

Tally board. Wi += dt × (write × write_signal × celli − fade × Wi). At food: Wi ×= (1 − erase). Note the write is driven only by the presynaptic side, the direction cell. That is the fly's rule as the anatomy suggests it: hΔB lands on the store in the matching column, and dopamine says when.

Reader. acti = Wi × (celli + 0.3). Arrow = Σ acti × (cos θi, sin θi). The 0.3 is a tonic drive so every column speaks a little even when its cell is silent; without it the brain would be blind to the direction opposite its travel. Then rotate by the rotation number.

Steerer. turn = gain × sin(arrow angle − heading) × cleanness, where cleanness = |arrow| / Σ acti, near 1 when the tallies agree on one direction and near 0 when they cancel. That last factor is what makes the agent stop at home: after walking back, north and south tallies match, the arrow vanishes, cleanness is 0, turning stops. This is the Mussells Pires and Westeinde PFL3 rule.

The code, explained brain1.py
# brain1.py  – the fly's four parts by hand. Only the six numbers in p are blank.
import numpy as np
from world import DT

COLS  = np.arange(8) * 2*np.pi/8   # the eight directions in radians: 0, 45°, 90° ... as 0, π/4, π/2 ...
TONIC = 0.3                        # background drive so every column can be read a little (see Go deeper)

def direction_cells(hd):
    # cos(angle difference) is 1 when the cell faces the heading, 0 at 90°, -1 behind.
    # np.maximum(0, ...) clips negatives to 0 because neurons cannot fire negatively.
    return np.maximum(0.0, np.cos(COLS - hd))

def brain_tick(W, s, p, at_food):
    # W: the eight tallies, a numpy array we change IN PLACE (W += ...) so the caller's
    #    array is the memory that carries across ticks and across trips.
    # s: the world state dict. p: the six numbers. at_food: True while standing at food.
    cells = direction_cells(s['hd'])

    # --- write signal: how much may the tallies grow this tick ---
    moving = 1.0 if s['speed'] > 0 else 0.0
    # speed_dep blends two ideas: 0 = "on while moving" (a switch), 1 = "scaled by speed".
    # The search decides which. Distance needs speed, so we expect it to pick 1.
    write_signal = p['speed_dep']*s['speed'] + (1-p['speed_dep'])*moving

    # --- the tally update. This one line IS the continual learning. ---
    # Each column grows by its cell's activity (so only the current direction is written),
    # scaled by write strength and the gate, and leaks by fade * its own size.
    W += DT * (p['write']*write_signal*cells - p['fade']*W)
    if at_food: W *= (1 - p['erase'])     # erase=1 wipes clean; 0.5 halves; 0 never forgets

    # --- reader: each tally is read through its cell's current activity ---
    act = W * (cells + TONIC)
    ax, ay = np.sum(act*np.cos(COLS)), np.sum(act*np.sin(COLS))   # add eight arrows tip to tail

    # --- rotation: spin the arrow by p['rot'] degrees (standard 2D rotation formula) ---
    r = np.radians(p['rot'])
    rx, ry = ax*np.cos(r) - ay*np.sin(r), ax*np.sin(r) + ay*np.cos(r)

    # --- steerer: turn toward the rotated arrow, harder when the arrow is clean ---
    clean = np.hypot(rx, ry) / (np.sum(act) + 1e-9)   # 1e-9 avoids dividing by zero on an empty board
    turn  = p['gain'] * np.sin(np.arctan2(ry, rx) - s['hd']) * min(1.0, 2*clean)
    return turn

We never tell the candidate where home was. It only learns "you ended 7 units away, that is bad." That coarse feedback is all the search gets.

Check before searching. The fly's answer should score under about 1.5 with over 70 percent arriving. If it does not, fix the brain first. A search on a broken exam finds nonsense.
The code, explained exam1.py
# exam1.py  – score one candidate. The score is the only feedback the search ever gets.
from world import *; from brain1 import *

def run_trip(W, p, rng):
    # W is passed IN, not created here, so tallies carry over from the previous trip.
    # That is deliberate: if every trip began with a clean board, the erase number would
    # never matter and the search could not find it. A real fly gets no clean board either.
    s = new_trip(rng); food_ticks = 5            # stand at food for 5 ticks = 0.5 s so erase can fire
    while s['phase'] != 'done' and not s['arrived']:
        at_food = food_ticks > 0
        if at_food: food_ticks -= 1; s['speed'] = 0.0
        else: update_speed(s, rng)
        turn = brain_tick(W, s, p, at_food)     # brain reads the world, updates W, asks for a turn
        move(s, turn, rng)                      # world obeys the turn (only on the return)
    if s['arrived']:                             # reached food: stand there so erase can fire
        for _ in range(5): brain_tick(W, s, p, True)
    # Return the best distance achieved and whether it counted as arriving.
    return min(s['min_d'], np.hypot(s['x'], s['y'])), s['arrived']

def score(p, n_trips=50, seed=0):
    # Same seed => same trips, so two candidates scored with the same seed sat the same exam.
    rng = np.random.default_rng(seed); W = np.zeros(8)
    results = [run_trip(W, p, rng) for _ in range(n_trips)]
    dists   = [r[0] for r in results]
    arrived = [r[1] for r in results]
    return np.mean(dists), np.mean(arrived)     # (score, fraction arrived). Lower score = better.

The search

Guess, score, keep, nudge, repeat. Make 24 candidates with random dials. Score each on 12 trips. Keep the best 6. Make 18 new ones by copying the survivors and nudging every number a little. Repeat. No gradients, no GPU. Run it here.

Go deeper how nudging finds the answer without gradients

The nudge is blind. For each new slot, pick a survivor at random, copy it, and add to every dial a random amount from a bell curve with spread 8 percent of that dial's range. The nudge does not know whether it helps. The knowledge is in the selection: a parent at rotation 150 has children at 143, 152, 161. The one at 161 is closer to 180, scores better, and is more likely to survive. Nobody computed "higher is better"; the crowd kept the children that happened to move that way. This is an evolution strategy.

Gradient descent would instead compute, for each dial, which direction improves the score and by how much, and step all dials at once. Far more efficient, but it needs the score to be a smooth, calculable function of the dials. Our score comes from a random simulation with pauses and a hard "within half a unit" test, so there is no formula to differentiate. With six dials, the wasteful method is cheap. With 8,700 numbers at level 3 it would be hopeless, which is why level 3 switches methods.

Fresh trips every generation matter: if the trips never changed, a candidate could get good at those particular trips instead of at homing. Same seed within a generation keeps the comparison between candidates fair.

The code, explained search1.py
# search1.py  – the evolution strategy. Twelve lines do all the "training" at this level.
from exam1 import score

# Each dial's allowed range. A dict so we can loop over dials by name.
RANGES = dict(write=(0,2), speed_dep=(0,1), erase=(0,1), fade=(0,0.2), rot=(0,360), gain=(0,6))

def random_candidate(rng):
    # One dict of six numbers, each uniform inside its range. This is a "candidate brain".
    return {k: rng.uniform(lo, hi) for k, (lo, hi) in RANGES.items()}

def nudge(p, rng):
    # Copy p, add bell-curve noise of 8 % of the range to every dial, clip back into range.
    # The noise is blind: it does not know which direction is better. Selection does that.
    return {k: np.clip(p[k] + rng.normal()*0.08*(hi-lo), lo, hi) for k, (lo, hi) in RANGES.items()}

def evolve(seed, generations=150, pop=24, keep=6):
    rng = np.random.default_rng(seed)
    cands = [random_candidate(rng) for _ in range(pop)]
    history = []
    for g in range(generations):
        # Score everyone on the SAME trips (seed 1000+g) so this generation's exam is fair,
        # but a DIFFERENT exam from last generation so nobody can memorise it.
        scored = sorted(cands, key=lambda p: score(p, 50, seed=1000+g)[0])
        best = scored[0]; history.append(dict(best))          # keep a copy for plotting
        survivors = scored[:keep]                             # the best 6 live on unchanged
        children  = [nudge(survivors[rng.integers(keep)], rng) for _ in range(pop-keep)]
        cands = survivors + children                          # next generation: 6 + 18 = 24
    return history

# Run it twenty times from different starts and plot where the dials land.
# One search can get lucky or stuck; twenty landing in the same place is an answer.
finals = [evolve(seed)[-1] for seed in range(20)]
If the search does not converge: check the exam again with the fly's settings. If that scores well but the search does not find it, the nudges are too big (try 4 percent) or the population too small (try 48). If rotation lands at 180 only sometimes, look at the other dials of the runs where it did not: usually gain or write collapsed to zero, which makes rotation irrelevant. More runs or a bigger population fixes that trap.

At level 1 we wired "write while moving" and "erase at food" by hand. Now we take those away and ask the search what should trigger each. The question: does the model invent the dopamine and octopamine jobs by itself?

Two decision units, live

A decision unit is the simplest neuron: three inputs, each times a weight, plus a bias, squashed into 0 to 1. The write unit's output replaces the write signal. The erase unit's output multiplies every tally by (1 − output) every tick. Drag the weights and watch the lamps in the level 1 brain panel respond to the live world. Set the weights well and the agent homes; set them badly and it does not.

Go deeper what a sigmoid does and why the bias matters

The unit computes z = bias + wspeed×speed + wfood×food + wdistractor×distractor, then output = 1 / (1 + e−z). That last function is the sigmoid: it maps any z to 0..1, with z = 0 giving 0.5, z = −4 giving 0.02, z = +4 giving 0.98. So the bias sets the resting state. An erase unit with bias −8 and food weight +16 is off (0.0003) while walking and on (0.9997) at food. If the bias were 0 it would be half-on all the time, which is a fade. So at this level, fade is no longer a separate dial: it is whatever the erase unit does when nothing is happening.

The distractor is there so we can check the search learned to ignore something. Without it, the units have only two inputs and almost any solution uses them.

The code, explained brain2.py
# brain2.py  – level 1's brain, but the write and erase signals come from tiny learned units.
def sigmoid(z): return 1/(1+np.exp(-z))   # squashes any number into 0..1

def unit(w, speed, food, distractor):
    # w is a list of 4 weights: [bias, for speed, for food, for distractor].
    # A weighted sum then a squash: the simplest possible neuron.
    return sigmoid(w[0] + w[1]*speed + w[2]*food + w[3]*distractor)

def brain_tick2(W, s, p, at_food, distractor):
    cells = direction_cells(s['hd'])
    write_signal = unit(p['w_write'], s['speed'], float(at_food), distractor)
    erase_signal = unit(p['w_erase'], s['speed'], float(at_food), distractor)
    W += DT * p['write'] * write_signal * cells   # no speed_dep: the unit decides how speed matters
    W *= (1 - erase_signal)                       # applied EVERY tick; near 0 => nothing, near 1 => wipe
    # reader, rotation, steerer: exactly as brain1
    ...

# In the search, RANGES gains eight entries (each unit weight in -10..10) and loses
# speed_dep, erase and fade, since the units now do those jobs. 11 numbers in all.
# The distractor is a slow sine plus noise, seeded independently of the wandering:
distractor = np.clip(0.5 + 0.5*np.sin(0.7*s['t'] + 1.3) + 0.1*rng.normal(), 0, 1)

Level 3

our own model · the goaltwo to three weeks · laptop, a small GPU helps

Now we throw the fly's parts away. No direction cells, no tally board, no reader, no turn-around. What is left is a plain network of 64 neurons, all connected to each other. Its inputs are heading, speed and food as raw numbers. Its outputs are a turn command for the legs and two gate signals, write and erase, that act only on its own memory. Nothing in it knows what a compass direction is.

The one fly-like thing it keeps: every connection has two strengths. A slow one, set by training and then frozen. And a fast one, starting at zero, changing while the model runs, by one simple rule. The network itself produces the write and erase signals that control the rule. So it decides, moment by moment, when to rewrite its own connections. This cannot be trained in a web page, so the two demos below teach the two ideas you need, and the code is complete.

Demo 1 · the rule that changes connections

Six neurons and the table of fast strengths between them. Click neurons to switch them on or off. Set the write and erase gates. Press Tick. The rule: when write is on, the connection from j to i grows by write strength × write × xi × xj. When erase is on, every connection shrinks toward zero. Write strength is the same idea as level 1's write dial: how much one tick of writing adds. It is one trained number that then stays fixed. It is not the learning rate that training uses, which is a different number and only exists while training runs. This is "cells that fire together wire together," gated.

Neurons · click to toggle

Try: turn on neurons 1 and 3, tick five times, then turn on 2 and 4 and tick five more. Then set erase to 1 and tick once.

F · fast strengths, row i ← column j

Amber: positive, grows when both neurons are on together. The diagonal is a neuron strengthening itself. In level 3 this table is 64 by 64 and there is one per trip.

Why this rule and not the fly's exact rule. The level 1 tally was "add the presynaptic activity." This rule is more general: it includes that case (when the receiving neuron is always on) but lets the network use both sides. We give it the general form because we are not supposed to hand it the answer. If, after training, the network uses it in the fly's way, that is a finding.

Demo 2 · why level 3 needs gradient descent

The search from levels 1 and 2 nudges blindly. With 8,700 numbers, blind nudging almost never improves anything. Gradient descent instead asks every number "which way makes the score better?" and steps them all at once. Here is a two-number version: the landscape is the score, low is good, and the ball is the model. Compare the two methods.

gradient descentrandom search (keep if better)

Reading it. The amber ball feels the slope under it and moves downhill every step. The blue ball tries a random nudge and keeps it only if the score improved; most nudges are wasted. In two dimensions blue still gets there. In 8,700 dimensions a random nudge is almost always uphill in most of them, and blue never arrives.

The learning rate is the step size. Too small and it crawls; too big and it overshoots the valley and bounces. Level 3 uses 0.001 with an optimiser called Adam that adapts the step per number.

The catch. Gradient descent needs to compute the slope, which means the score must be a smooth function of the numbers. "Did it arrive within 0.5" is a cliff, not a slope. So level 3 scores by distance from food, which changes smoothly, and PyTorch computes the slope of that distance with respect to all 8,700 numbers by tracing backwards through every tick of the trip, including every change to F. That trace is backpropagation; through the fast-weight rule it is called differentiable plasticity.

The build, step by step

  1. Build the network (code below). About 8,700 trained numbers: the input weights, the slow table W, the table A that says how much each connection may use its fast strength, the output weights, and the rule's write strength.
  2. Write the world in PyTorch, running 64 trips side by side. Two trips per episode with F carried over, so the network must learn to erase.
  3. Train for about 4,000 iterations. Loss starts near 7 (a random walk) and should fall below 1.5.
  4. Freeze and test on 200 new trips. If it still homes, the fast strengths carried the memory. Then force F to zero every tick and confirm it now fails: that proves where the memory lived.
  5. Look inside: direction tuning per neuron, F traces over a trip, gate traces against speed and food.
The code, explained flynet.py · the network
# flynet.py  – our own model. No compass columns, no tally board. Just neurons and a rule.
import torch, torch.nn as nn
N = 64   # neurons. Enough to hold a vector many ways; small enough to inspect.

class FlyNet(nn.Module):           # nn.Module: PyTorch's base class; it tracks trainable numbers for us
    def __init__(self):
        super().__init__()
        self.W_in  = nn.Linear(4, N)      # 4 inputs -> 64 neurons. nn.Linear = a weight table plus a bias.
        # nn.Parameter marks a tensor as "train this". W starts small and random (0.1*randn)
        # so the network is not silent and not exploding at the start.
        self.W     = nn.Parameter(0.1*torch.randn(N, N))    # SLOW strengths, neuron j -> neuron i
        self.A     = nn.Parameter(0.01*torch.randn(N, N))   # per-connection: how much FAST strength counts
        self.W_out = nn.Linear(N, 3)      # 64 neurons -> 3 outputs: turn, write gate, erase gate
        self.ws    = nn.Parameter(torch.tensor(0.1))        # the rule's WRITE STRENGTH (level 1's write dial), also trained.
                                                             # Not the training learning rate: that one belongs to Adam, below.

    def start(self, batch):
        # Fresh neurons (all 0) and a fresh fast table (all 0) for each of `batch` trips.
        # Shape [batch, N, N]: one 64x64 fast table PER trip, because each agent has its own memory.
        return torch.zeros(batch, N), torch.zeros(batch, N, N)

    def step(self, x, F, inp):
        # x: [batch, N] current neuron values. F: [batch, N, N] fast strengths. inp: [batch, 4].
        eff = self.W + self.A * F         # effective strength = slow + (allowance * fast). Broadcasts W over the batch.
        # bmm = batched matrix multiply: for each trip, eff @ x gives what every neuron hears
        # from every other neuron. unsqueeze/squeeze just shape x as a column for the multiply.
        recurrent = torch.bmm(eff, x.unsqueeze(2)).squeeze(2)
        x_new = torch.tanh(self.W_in(inp) + recurrent)   # tanh keeps every neuron in -1..1

        out   = self.W_out(x_new)
        turn  = out[:, 0]                          # any value; radians per second
        write = torch.sigmoid(out[:, 1])           # 0..1: the network's own "write now"
        erase = torch.sigmoid(out[:, 2])           # 0..1: the network's own "erase now"

        # --- the rule. This is the continual learning. ---
        # hebb[i][j] = x_new[i] * x_old[j]: big when both ends are active together.
        hebb = x_new.unsqueeze(2) * x.unsqueeze(1)        # outer product, shape [batch, N, N]
        # [:, None, None] reshapes the per-trip gate so it multiplies a whole table.
        F = (1 - erase[:, None, None]) * F + self.ws * write[:, None, None] * hebb
        F = F.clamp(-1, 1)                         # fast strengths can never blow up
        return x_new, F, turn, write, erase
The code, explained world_torch.py · the batched world and the loss
# world_torch.py  – the same world, but 64 trips at once, and a smooth score.
from flynet import *
DT, T_OUT, T_RET = 0.1, 30.0, 60.0

def run_episode(net, batch=64, n_trips=2, seed=None):
    # An episode = n_trips trips in a row. F carries over between trips (the network must
    # learn to erase); x is reset each trip (a fresh "now"). Returns the loss to minimise.
    g = torch.Generator().manual_seed(seed) if seed is not None else None   # seed for reproducible tests
    x, F = net.start(batch)
    losses = []
    for trip in range(n_trips):
        pos = torch.zeros(batch, 2)                                  # everyone starts at food
        hd  = torch.rand(batch, generator=g) * 6.2832                # random heading, 0..2π
        speed = torch.ones(batch); x = torch.zeros(batch, N)
        for k in range(int((T_OUT + T_RET)/DT)):                    # 900 ticks
            t = k*DT
            returning = 1.0 if t >= T_OUT else 0.0                  # the switch
            food  = torch.full((batch,), 1.0 if t < 0.5 else 0.0)   # at food for the first half second
            speed = (speed + 0.3*torch.randn(batch, generator=g)*DT**0.5 + 0.2*(1-speed)*DT).clamp(0.3, 1.7)
            speed = speed * (1 - food)                               # standing still at food
            # Heading goes in as cos and sin, not a raw angle, so 359° and 1° look like neighbours.
            inp = torch.stack([torch.cos(hd), torch.sin(hd), speed, food], 1)
            x, F, turn, write, erase = net.step(x, F, inp)
            hd  = hd + returning*turn*DT + 0.8*torch.randn(batch, generator=g)*DT**0.5
            pos = pos + speed[:, None] * torch.stack([torch.cos(hd), torch.sin(hd)], 1) * DT
            if t >= T_OUT + T_RET - 10:                                # last 10 s of the return
                losses.append(pos.norm(dim=1))                       # distance from food: SMOOTH, so gradients flow
        for _ in range(5):                                           # stand at food so erase can fire before the next trip
            inp = torch.stack([torch.cos(hd), torch.sin(hd), torch.zeros(batch), torch.ones(batch)], 1)
            x, F, *_ = net.step(x, F, inp)
    return torch.stack(losses).mean()    # one number. Lower = closer to home at the end.
Do not reset F at the start of a trip. It is tempting and it makes training easier, but it hands the network the erase for free and the result no longer tests the fly's design.
The code, explained train3.py · training, freezing, proving
# train3.py
from world_torch import *
torch.manual_seed(0)
net = FlyNet()
# Adam: gradient descent with a per-number adaptive step. lr=1e-3 is the usual safe start.
# THIS is the learning rate: how far each slow parameter moves per training step. Gone after training.
opt = torch.optim.Adam(net.parameters(), lr=1e-3)

for it in range(4000):
    loss = run_episode(net, batch=64, n_trips=2)   # fresh random trips every iteration: nothing to memorise
    opt.zero_grad()                               # clear last iteration's slopes
    loss.backward()                               # backpropagation: slope of loss w.r.t. all 8,700 numbers,
                                                  # traced back through 1,800 ticks INCLUDING every change to F
    torch.nn.utils.clip_grad_norm_(net.parameters(), 1.0)   # cap the step so one wild episode cannot wreck training
    opt.step()                                    # move every number a little downhill
    if it % 50 == 0: print(it, float(loss))       # expect ~7 at the start, under 1.5 by the end
torch.save(net.state_dict(), 'flynet.pt')

    print('frozen, new trips:', float(run_episode(net, batch=200, n_trips=2, seed=999)))

Go deeper looking inside, and the four ways it fails

Three plots. Direction tuning: for each neuron, average activity against heading in 16 bins around the circle; fly-like neurons show one bump, and the bumps should spread around the circle. Tally-like F: take the connections with the largest A and plot their F over a trip; fly-like ones grow with distance walked in some direction and drop at food. Gates: write and erase over a trip against speed and food.

  • Loss never drops below 5. Stuck. Try Adam at 3e-4, 128 neurons, or a curriculum: 10-second outbound first, lengthen once it works. Last resort: evolution on all 8,700 numbers, slow but gradient-free.
  • Trains well, frozen test bad. Memorised. Fresh seeds every iteration (the code does), more varied trips, and the F-zeroed check.
  • Homes but F stays near zero. Found the activity solution. Not wrong, just not the fly. Make it need F: 60-second outbound, compass noise, or 16 neurons so there is not enough activity to hold a sum. If it then switches to F, that is a result about when fast weights become necessary.
  • Gates always on. Using fade instead of erase. Add a tiny loss penalty for the erase gate being on, so it fires only when it pays.

The code, explained rival and stress tests
# rival.py  – the same network with fast weights removed. Its only memory is activity.
class RivalNet(FlyNet):
    def __init__(self):
        super().__init__()
        self.A.requires_grad_(False)   # never train the allowance table...
        self.A.zero_()                 # ...and set it to zero: F can change all it likes, it counts for nothing
# Train it EXACTLY as FlyNet was trained: same world, loss, iterations, batch. It must be tuned
# just as carefully or the comparison is unfair. It will probably learn to home on 30 s trips.

# stress.py  – freeze both, make the world harder, no retraining.
def stress(net, t_out, drift=0.0, seed=7):
    # t_out: outbound seconds. drift: compass noise. run_episode needs two small changes:
    #   1. T_OUT and T_RET become arguments (T_RET = 2*t_out).
    #   2. the heading fed to the network is hd + comp, where comp does a random walk with spread `drift`,
    #      while the physics still uses the true hd. The agent steers by a compass that lies a little.
    with torch.no_grad():
        return float(run_episode(net, batch=200, n_trips=2, seed=seed, t_out=t_out, drift=drift))

Words that came up

Write strength
How much one tick of writing adds to a fast weight. Level 1's write dial; in level 3, one trained number inside the rule. Not the same thing as the learning rate.
Learning rate
The step size gradient descent uses to move the slow weights during training. Only exists while training runs. The confusing part is that the field uses the same words for the write strength inside a plasticity rule; this page does not.
Fast weights
Connection strengths that change while the model runs. The tally marks. In level 3, the table F.
Slow weights
Set by training, then frozen. The wiring and the rulebook. In the fly, the genes. In level 3, W, A and the rest.
Loop gain
How much an activity memory multiplies itself by each moment. Must be exactly 1 to hold a number. The slider at the top.
The search
Guess, score, keep the best, nudge, repeat. An evolution strategy. Good for a dozen numbers. Levels 1 and 2.
Gradient descent
Compute which way improves the score for every number at once, step them all. Needs a smooth score. Levels 3 and 4.
Backpropagation
The bookkeeping that computes those directions by tracing backwards through every calculation. loss.backward().
Differentiable plasticity
Backpropagation run through the fast-weight changes too, so training can shape the rule and the gates. Miconi, 2018.
Hebbian rule
"Cells that fire together wire together." Demo 1 in level 3.
Sigmoid
Squashes any number into 0..1. Turns a weighted sum into an on/off-ish gate.
Loss and score
The same idea: how far from food, averaged over random trips. Lower is better. The only feedback there is.
Batch
Many trips run side by side so the computer does them at once. 64 in level 3.
Frozen
Training is off. Anything the model still learns after this, it learns by fast weights.
