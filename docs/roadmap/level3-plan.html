Level 3 Training Plan

How we train a 64-neuron network, from random numbers, to find its way home by rewriting its own connections. What gets built, in what order, why each choice, what the machine will do, how long it takes, how we know it worked, and what to do when it does not. Nothing here has run yet.

What "done" means

A frozen network that homes on trips it has never seen, and gets lost when its fast strengths are held at zero. Same 8,700 numbers both times. The gap is the memory.

Why this matters. One training iteration is 64 agents, 1,800 ticks each, a 64-by-64 multiply per tick, then the same again backwards. That is small. The laptop does it in well under a second per iteration. The whole first run is about half an hour, so we can afford to be wrong several times in an afternoon. The GPU helps but is not required.

Build order, and why that order

Each step is checked before the next starts, so a bug is found where it was made. The rule that shaped this order: never debug the network and the world at the same time.

Step 1 · half a day

The world in PyTorch

Port the level 2 world exactly: drifting speed, pauses, half a second at food, the tally ceiling, the freeze after arrival, 64 agents side by side, two trips per episode. Every operation must be one PyTorch can trace backwards.

Check before moving onDrop the level 1 hand-built brain into it. It must score about 0.6, the same as in numpy. If it does not, the world is wrong and nothing after it means anything.
Step 2 · half a day

The network

FlyNet as on the roadmap: input weights, W, A, output weights, write strength, the Hebbian rule with two gates. Plus one switch that disables A, which gives us brain B and the level 4 rival for free.

CheckAn untrained network runs an episode without errors and scores about 7, a random walk. Then fifty iterations of training: the score must move. If it sits at 7.0 exactly, gradients are not flowing.
Step 3 · half an hour per run

Train, with a curriculum · about 30 minutes

Run 1: ten-second wanders, then twenty, batch 32, 3,000 iterations, about half an hour. Run 2, only if run 1 passes its tests: start from run 1's weights and stretch to thirty seconds. Each stage starts from the last stage's numbers. Checkpoints saved every 100 iterations. A training page shows the score, the gates on a sample trip, and the F-zeroed score at every checkpoint, so we watch where the memory is going as it learns.

CheckTen-second stage under 1.5 within a few hundred iterations. Twenty-second stage under 1.5 by the end of run 1. Thirty seconds is run 2.
Step 4 · half a day

Freeze and test

Load the best checkpoint. Run brain A (F allowed), brain B (F held at zero), brain C (random walk) on the same 200 trips. The three-bar chart.

CheckA under 1.5, B near 7. That is the goal. Any other pattern goes to the playbook below.
Step 5 · half a day

Look inside

Four pictures: each neuron's activity around the compass, F on the highest-A connections over a trip, the two gates against speed and food, and a heatmap of A itself, which is a map of where training put the tally board.

Step 6 · a day

Write it up

A fifth findings page: what was known, what we found, why it matters, what the evidence is. With the caveats: the shape of the rule was ours, 64 neurons was ours, the world is a plane with a perfect compass.

What the number of neurons does to cost. The two tables W and A are 64 × 64 each, and the multiply per tick is 64 × 64 per agent. Double the neurons and both quadruple. That is why 64 is the first run and 128 is a second experiment, not a default.

The curriculum, and why not just train on 30-second trips

Backpropagation through 900 ticks from a random start often finds nothing: the slope of the score with respect to something that happened 80 seconds earlier is tiny and noisy. Through 300 ticks it usually finds something. So we train on short trips first, then lengthen them once the network has a working memory, and let it stretch what it already has.

Illustrative shape: each stage starts with a bump, because longer trips are harder, and settles. Promotion happens when the score crosses the line.

The checks along the way

Each one is cheap and each one catches a class of bug before it costs a night. They run in this order, and none is skipped.

checkwhenpasswhat a fail means
World checkafter step 1level 1 hand brain scores ≈ 0.6 in torchthe torch world differs from numpy; fix before anything else
Random checkafter step 2untrained net scores ≈ 7the net is steering by accident, or the world is broken
Gradient check50 iterationsscore has moved from 7gradients not flowing: a detach, a clamp, or a wrong loss
Stage checkeach stageunder 1.5 before promotionlearning rate, neurons, or stage too long
Drift checkevery checkpointF-zeroed score rising over trainingif it stays low, the net is choosing activity; tighten the task early, not at the end
Frozen checkstep 4new-trip score within 20 % of trainingmemorised the training trips
F-zeroed checkstep 4score near 7memory in activity: see playbook
The drift check is the one people skip. Running the F-zeroed test only at the end tells you where the memory ended up. Running it at every checkpoint tells you where it was heading, so if the network is settling into the activity solution you find out at iteration 500 and can make the task harder then, instead of discovering it after a full night.

What success is

Three brains, the same 200 trips, one number each. Brain A is the trained network. Brain B is the identical network with its fast strengths held at zero every tick. Brain C is a random walk. Click the outcomes.

The reason this is a clean test: A and B share every one of the 8,700 trained numbers, and the neuron activity is reset at the start of every trip. Between second 0 and second 30 of a trip, the only thing that can change is F. If A homes and B does not, whatever A learned during the trip lived in F.

What gets written

All in a new level3/ folder in the fork, next to levels 1 and 2, with the same local-app pattern: a Python server, a page with buttons and accumulating charts, and the source shown in tabs.

world.pyThe batched torch world. Speed drift, pauses, food stand, ceiling, arrival freeze. Returns the smooth loss.
flynet.pyThe network and the rule. One flag disables A for brain B and the rival.
handbrain.pyThe level 1 brain written in torch, for the world check only.
train.pyCurriculum, checkpoints every 100 iterations, the drift check, logs to a JSON the page reads.
test.pyThree brains on the same trips, the look-inside plots, saved as PNGs and JSON.
server.py + index.htmlStart, pause, resume training; the charts; load a checkpoint; run the tests; the code tabs.
