# What we learned about training

_This file is written by the supervisor as the night goes on and rendered into the report. Every claim names the run it comes from._

## The curriculum was necessary, and it is where the swings live
Runs 1 and 2 never earned their promotion to 20-second trips; they hit the 1,500-iteration cap. Run 3 earned it at iteration 804. Every run's cost per iteration doubled at the switch, because an episode is twice as long and training walks through every tick twice, forward and backward.

## The bad swings were the optimiser overshooting near the ceiling
Run 1 at iteration 800 and run 3 at iteration 1900 both lost most of their score in about thirty iterations. In run 3 the write gate nearly doubled (0.39 to 0.71) and the tallies saturated; a saturated tally does not just forget, it points the wrong way, so the loss went above a random walk. Adam's momentum carried a step that a few batches had asked for. Both recovered within a hundred iterations. Checkpoints every hundred iterations are what make this survivable.

## A fade is the easy solution, and it is not the fly's
Every run so far erases at about one percent per tick and never fires at food. The signal to fire at food is tiny (a few ticks per trip) and its payoff is delayed to the next trip. The reset is the one fly ingredient no run has found. Run 4 tests whether making leftovers hurt more (five trips per episode) changes that.

## Speed-weighted writing appeared once the write gate had room
Run 3's write gate follows speed with correlation +0.94; runs 1 and 2 were flat. The difference was not a knob about speed. It was that the two-second food stand lowered the overall write level and left the tallies off the ceiling, and in that regime speed-weighting pays.

## Making leftovers hurt more did not teach the reset (run 4)
Five trips per episode instead of two, warm from run 3. The first hundred iterations were a shock (score 3.06, up from 1.72) as the fade struggled with a board dirtied by three or four earlier trips, then the network settled back to about 1.7 by fading a little harder. The erase gate at food did not move: 0.0045, lower than away from food. The prediction failed, and the score at 20 s ended worse than the parent (2.30 vs 1.90). Lesson: the reset is not going to be forced by punishing a dirty board; the gate simply cannot see the five or twenty food ticks against the hundreds of others. The one useful thing run 4 gave is the first 30-second score, 2.37 at its best checkpoint, on trips longer than anything it trained on.

## Why the ceiling is not a clean lever (a decision, not a run)
Lowering the tally ceiling looked like the other way to force a reset. But the write strength and the A table are both trained, so the network can halve what it writes and double how loudly F counts, and a lower ceiling changes nothing. Skipped, and the reason is recorded here so it is not re-tried by accident.

## Run 5: the penalty again, but from a warm start
Run 2 raised the erase penalty from a cold start and got a dead network: with nothing yet learned, the penalty just closed the gate. Run 3's best checkpoint already homes, already has compass cells and a speed-following write gate, and a fade of about one percent per tick. Charging that fade ten times more, now that there is a working memory to protect, may push the erasing that remains into the one place it is free: the food ticks. Same parent as run 4, two trips, penalty 0.5. Prediction: erase at food rises above 0.1 while erase away from food falls below 0.003; score at 20 s stays near 1.9. Failure looks like run 2: the gate closes everywhere and the tallies saturate.

## The penalty knob was never really connected (run 5)
Warm from run 3, erase penalty 0.5. The gate did not move, and the arithmetic says why: 0.5 times a gate of 0.01 adds about 0.005 to a loss of about 2. Run 2's death was a cold-start problem, not the penalty biting. If we want the penalty to matter it needs to be in the tens, and that is a legal knob still on the table.

## Late collapses are now the main enemy (runs 3, 4, 5)
Run 5 reached the best frozen exam of the night at iteration 400 (1.41 at 20 s), then collapsed at 500, recovered, and collapsed again at 1000 without recovering; its final network scores worse than a random walk. Every collapse looks the same in the log: the write gate jumps, the tallies saturate, and the loss goes above random because a saturated tally steers the wrong way. Adam's step size is constant through the run, so late in a run, when the network sits close to its best, one noisy batch can still throw it. From run 6 on, the learning rate decays with a cosine schedule to zero over the run, declared as hygiene rather than a scientific knob, so late steps are small.

## Run 6: earn the 30-second score, with the schedule
Warm from run 5's best checkpoint (the 1.41 exam), 30-second wanders, two trips, cosine learning-rate decay. One scientific change (the stage) plus the hygiene. Prediction: no collapse after iteration 600; a 30-second score at or under 2.0 with the memory in F, against the untrained-at-30 baseline of 2.37 from runs 4 and 5.

## Decay alone did not stop the collapse (run 6, killed at 600)
Run 6 trained at 30 seconds and got to a frozen exam of 1.77 by iteration 400, the best 30-second number so far and well under the untrained 2.37. Then the same collapse: write gate 0.38 to 0.64 in a hundred iterations, loss above 12. With a cosine schedule over 1,200 iterations, the learning rate at iteration 500 was still about two thirds of the starting rate, so the schedule had not yet done anything. Killed at 600 rather than spend twenty minutes hoping. Run 6B restarts from run 6's own best checkpoint with the base rate cut to a third and the same decay. If that holds, the rule for the rest of the night is: warm starts train at 3e-4, not 1e-3.

## An honest note on how the 30-second stage was started
The rule said: promote to 30 seconds only when the running score at 20 seconds is under 1.5. No run met that; run 3 bottomed at about 1.65 and run 5 at 1.74. Run 6 was started on a looser reading: run 5's checkpoint 400 scored 1.41 on the frozen 64-trip drift check, which is a cleaner number than the running score but a smaller exam than the 200-trip test, where the best 20-second score is 1.90. So the 30-second line began before the strict criterion was met. It is kept because the memory plainly transfers to 30 seconds (2.19 earned, 5.85 without F), but the label should be accurate: the stretch was started early.

## The lower learning rate ended the collapses (run 6B)
Same checkpoint, same 30-second trips, learning rate cut from 1e-3 to 3e-4 with cosine decay: 800 iterations with no collapse, where run 6 fell over at 500. The final network scores 2.13 at 30 seconds with its memory and 5.91 without, the best earned 30-second number so far. This settles the hygiene question for the night: warm starts train at 3e-4.

## What still separates 2.1 from the 0.75 floor
Three measured gaps, all visible on run 6B's panels. The erase gate is a fade (0.005 at food, 0.009 away), so early steps leak. The write gate follows speed only partly (+0.53), so distance is still partly time. And at 30 seconds a third of the tally ticks are at the ceiling, so late steps are lost. Each of these is a fly ingredient the network has not fully found. The next runs go after them one at a time.

## Run 7: a penalty that is actually large
The penalty knob was never connected: at 0.5 it added nothing to the loss. At 20 it adds about 0.17 per tick of fade, which is a real cost against a loss of about 3. Warm from run 6B at the safe learning rate, so the change is gradual and visible. Two outcomes are possible and both are informative: the gate moves its erasing to the food ticks (erase at food rises above 0.05, away below 0.002), or it closes everywhere and the tallies saturate, which would say this scalar gate cannot learn the reset from this signal at all.

## The erase gate was deaf, not stubborn (run 7, killed at 200)
With the penalty at 20 the gate still did not move: 0.0081 to 0.0075 away from food, and at food it went down. Then the reason became clear, and it is embarrassing in hindsight. The erase gate is a sigmoid, and at the start of level 3 I set its bias to -5 so that fast strengths could accumulate at all. A sigmoid at -5 outputs 0.007, and its slope there is also about 0.007. Every gradient that reaches the gate, whether from the penalty or from the benefit of a clean board, is multiplied by that slope before it can change the bias or the weights behind it. The write gate, started at +1 where the slope is 0.2, moves freely, which is why speed-weighting was learnable and the reset was not. This is the vanishing-gradient problem in miniature, inside one neuron. No knob about the world could have fixed it.

## Run 7B: give the gate a voice
Warm from run 6B, penalty 20, and the erase gate's bias shifted up by 2.5 at the start (from about -5 to about -2.5, resting erase about 0.08 per tick, slope about 0.07, ten times louder). That fade is far too strong, so the network will be pushed hard to bring erasing down away from food (the penalty and the memory both want that) and left free to keep it up at food, where erasing is not charged. If the reset is learnable at all by this gate, this is where it appears. Prediction: away-from-food erase falls below 0.01 within 300 iterations; at-food erase stays above 0.05; score at 30 s recovers to about 2.1 or better.

## The reset starts to appear once the gate can hear (run 7B)
With the erase bias shifted from about -5 to about -2.5, the gate moved within a hundred iterations: away-from-food erase fell from 0.080 to 0.011, as the penalty demanded, while at-food erase fell more slowly and then held. By the end, the 200-trip test shows 0.027 at food against 0.009 away, a ratio of three, with peaks of 0.06 during the food stand. No earlier run had a ratio above one. This is the fly's reset beginning to form, found by the network once the gradient could reach the gate. It is not a reset yet: a real one is near 1 at food and near 0 away. And it cost score, 2.55 at 30 s against 2.13, because the run began with a fade far too strong and 800 iterations at the low rate did not fully repair the memory.

## Run 8: let the same line keep going
Warm from run 7B, nothing else changed: penalty 20, no further bias shift, 1,200 iterations at 3e-4. The question is whether the food preference keeps sharpening on its own now that the gate is out of the flat region, and whether the score recovers. Prediction: ratio above 5, at-food erase above 0.05, score back to 2.2 or better. If the ratio stalls near 3, the gate has found a compromise and a stronger push (a larger bias shift or a longer food stand) is next.

## Left alone, the gate settles for a mild preference (run 8, killed at 300)
Run 8 continued run 7B with nothing changed. The score recovered to about 2.2, but the food-versus-away erase ratio on the sample trip stayed between 1.3 and 1.6 for 300 iterations, with peaks at food of no more than 0.10. The gate is no longer deaf, but the signal it hears is weak: erasing at food is free and slightly useful; erasing away is charged. That makes a small preference, not a reset. Killed at 300.

## Run 8B: more food ticks now that the gate can hear
The food stand goes from two seconds to four, from the recovered run 8 checkpoint. Run 3 tried a longer food stand when the gate was deaf and it only rebalanced the trip. Now that the gate hears, doubling the number of food ticks doubles the weight of "erasing here is free and helps the next trip" in every gradient. Prediction: the ratio on the sample trip rises above 4 within 400 iterations, at-food erase above 0.05, and the score holds near 2.2. If it does not move, the remaining lever is a second bias shift, which restarts the pressure that produced the first preference.

## Run 9: does the reset appear from scratch when the gate can hear?
Every reset attempt so far has been a warm start on top of a fade the network had already settled into. Run 9 starts from random numbers, like runs 1 to 3, with two changes made together because neither works alone: the erase gate rests at -2.5 instead of -5 so its gradients are not crushed, and the penalty is 20 so that fading is expensive from the first iteration. Full curriculum, 10 then 20 then 30 seconds. This is the decisive test of whether the reset is learnable in this world, and a replication of the compass cells and speed-following write gate from a cold start. Prediction: ratio above 5 by the 20-second stage, at-food erase above 0.1. If a network that has never known a fade still chooses one, the reset needs a signal this world does not provide, and that is the finding.

## More food ticks did not sharpen the reset either (run 8B)
Four seconds at food instead of two, from run 8's recovered checkpoint. The ratio on the 200-trip test came out at 3.0, the same mild preference run 7B had, and the score held at 2.28 on the standard exam. So on the warm-start line, the reset has a ceiling near a ratio of 3 that neither continuing (run 8) nor more food (run 8B) lifts. Two explanations are left: the fade the network settled into early is a valley it will not leave, or the signal for a clean reset is simply weak in this world. Run 9 separates them by starting from scratch with the gate audible from the first iteration.

## A cold start with penalty 20 shuts the gate before it learns anything (run 9, killed at 300)
The same penalty that a trained network could absorb crushed a fresh one: within 200 iterations the erase gate went to 0.0001 per tick, back into the flat part of the sigmoid where it is deaf, and no memory had formed yet. Run 2 again, for the same reason. The order matters: the gate has to stay audible while the tally board is being built, and only then can a cost on fading shape it. Run 9B keeps the audible bias and cuts the penalty to 2, which still makes a one-percent fade cost about 0.02 per tick, a tenth of run 9's push.

## Order of learning: the tally first, the reset second (run 9B, killed at 500)
Even with the penalty cut to 2, a fresh network with an audible erase gate never formed a memory: at iteration 500 the frozen brain scored the same with and without F. Two things went wrong at once. Before a tally exists, erasing has no upside, so every gradient pushes the gate shut, and by iteration 200 it was at 0.001 per tick, deaf again. And the strong fade it started with wiped whatever tallies were beginning to form. Run 3, the same seed with a deaf gate, had a memory by iteration 300. So the audible gate is a warm-start tool: it helps a network that already homes (run 7B) and hurts one that does not. The fly presumably solves this by having the two systems on different timescales; evolution wired the store before the reset had anything to protect. In our training the order is the same: tally first, then reset.

## The ratchet works, and single-trip checks hid it (run 10)
A second bias shift on top of run 8B took the food-versus-away erase ratio from 3 to 7.4 on the 200-trip test: 0.075 per tick at food, 0.010 away, with peaks of 0.20 on the test trip and 0.2 to 0.3 during training, where earlier runs peaked near 0.06. On the single-trip training check the ratio looked stuck near 1.8, which is a lesson about measurement: one trip is too noisy to read a gate that fires on a handful of ticks. The reset is now a spike that fires at food and nowhere else, a third of the way to the fly's clean wipe. And the same run produced the best earned 30-second score, 2.10 on the standard exam with frozen checks under 1.5. Moving the reset forward moved the score forward.

## Runs 11 to 13, queued from what the night has shown
Run 11 is a replication: run 3's recipe from a different random start (seed 1), to check that compass cells and speed-following writing are not a property of seed 0. Run 12 pushes the ratchet a third time from run 10, to see whether the reset keeps sharpening or two shifts were the limit. Run 13 changes the world so that time and distance disagree, the slow-half fast-half wanders, warm from run 10; it is the hard test of speed-weighted writing, and the hand brain's floor on that world is 1.08.

## The recipe replicates at 10 seconds; the 20-second transfer is seed-dependent (run 11)
Seed 1 learned to home at 10 seconds faster than seed 0 did, and with a wider frozen gap. Then it stalled at 20 seconds for 400 iterations and the driver stopped it. Its write gate was high (0.7) and its write strength had grown to 0.10, which is the run 1 signature: a tally that fills to the ceiling on longer trips. Seed 0 in run 3 went through the same stall and came out of it after about 200 iterations; seed 1 had 400 and did not. Either it needed longer, or seeds differ in how easily they lower the write gate when the trip lengthens. Run 11B gives it the time, with the gap rule suspended, so the two explanations can be told apart.

## Three shifts, three steps toward the wipe (run 12)
Each bias shift restarts the same pressure, and each time the gate settles higher at food than before: ratios of 3, then 7, then 20, with peaks at food of 0.06, then 0.2, then 0.50. Away from food the gate stays near 0.01 throughout, held there by the penalty. This is the reset being assembled in stages, and it is worth saying what the stages are: the shift forces a strong fade; the penalty and the memory push the fade down everywhere; the only place erasing is free is at food, so that is where the gate keeps some of it; and each round leaves more there than the last. Run 12's score, 2.21 at 30 seconds, is within noise of run 10's 2.10, so the reset is not being bought with homing.

## A harder world made a better brain (run 13)
Run 13 trained on wanders with a slow half and a fast half, so that a tally counting time would point the wrong way. Tested back on the standard world it scored 1.98 at 30 seconds, and 1.91 at its best checkpoint, the lowest earned numbers of the night, with the memory still in F (5.9 without it). Write-versus-speed rose to +0.69, not the 0.9 predicted, so the network did not become a pure distance counter; it became a better mixture. The reset it inherited from run 10 survived the change of world. The general lesson is one that training people know: a curriculum that makes the shortcut fail teaches the real skill, and the real skill transfers back.

## A collaborator's note, and run 15
While the campaign ran, Peter pushed a note to the fork (docs/flynet-delta-rule.md) placing FlyNet in the literature: it is Miconi's differentiable plasticity with Backpropamine's self-produced write gate, plus a self-produced erase gate, and its Hebbian write is a gradient step on a linear inner objective that has no best value, which is why F needs a clamp and why the erase gate has been the hard part. He proposes the one-line alternative from the 2024-25 sequence-model work, the delta rule: write only the part of the new activity that F failed to predict. It self-limits, so the erase gate's job changes from "stop F filling up" to "forget the last trip". Run 15 tries it from a cold start with run 3's recipe, so the rule is the only difference, with his prediction recorded before the run.

## Seed 1 transfers to 20 seconds, slowly (run 11B)
With the gap rule suspended, seed 1's memory gap opened over 800 iterations to about 0.8 and its score fell from 4.4 to 3.7, so it was a matter of time and not a dead end. But it is far behind seed 0 at the same age: on the standard 20-second test it scores 3.87, worse than a random walk, with its tallies saturated 59% of the time and a write strength twice seed 0's. The honest version of the replication claim is therefore narrow. Compass cells and a working 10-second tally emerge from either seed. How quickly the network learns to write less when the trip gets longer depends on where it started, and that is the step where our one-size curriculum is fragile.

## Four shifts: the spike is nearly a wipe (run 14)
Run 14 fires its erase gate at food 0.37 per tick on average and 0.78 at the peak, against 0.01 away from food. On the training checks the peaks reached 0.9. The fly's clean wipe would be 1 at food and 0 away; this network is most of the way there, and it got there in four rounds of the same move, each round leaving more erasing at the one place erasing is free. Its score, 2.06 at 30 seconds with 26% arriving, is as good as any run of the night. So the reset was learnable after all. What it needed was not a cleverer world but a gate that could hear, a working memory to protect, a cost on fading, and repetition.

## The delta rule predicts instead of counting (run 15)
Peter's one-line change replaces "write the pattern" with "write only the surprise". From a cold start it formed no memory in 800 iterations and the driver stopped it. The reason is visible in the numbers: the write strength and A froze after the first hundred iterations, which means F had stopped changing and there was nothing for the outer loop to tune. A delta rule drives F toward predicting the next activity from the current one; once it can, the surprise is zero and writing stops. That is the right behaviour for a sequence model that wants to store associations, and the wrong one for a tally that has to keep adding the same direction step after step. The Hebbian write, which never stops adding, is the one that counts. This is a real negative result for the sequence-model reading of the fly's store, with the caveat that only the cold-start form was tried.
